# Claude Instructions: PH626 Kaakbay CDC LMS User Manual Presentation

Create a complete, practical PowerPoint user manual for the **PH626 Kaakbay Child Development Center Learning Management System (LMS)**. The audience includes participants/students, teachers, administrators, and first-time users with limited technical experience.

## Source of Truth

Use the attached project files, application screenshots, and live application behavior as the source of truth. Do not invent features, buttons, permissions, reports, credentials, URLs, or workflows. If a behavior cannot be confirmed, label it **To be confirmed by the LMS administrator** instead of presenting it as fact.

Use the exact labels displayed in the application where possible. Correct obvious spelling errors in explanatory text, but mention the exact on-screen label in parentheses when it may help users find it.

## Presentation Goal

The finished presentation must allow a new user to:

- Understand what the LMS is for.
- Sign in and recover from common sign-in problems.
- Recognize which tools are available for their role.
- Complete the most common tasks step by step.
- Understand statuses, notifications, confirmations, errors, and required fields.
- Protect account information and use the system responsibly.
- Know what to do when a task or page is unavailable.

Write in plain, friendly English. Use short sentences and action verbs such as **Open**, **Select**, **Enter**, **Upload**, **Submit**, **Review**, and **Confirm**.

## Required Slide Structure

Create approximately 24 to 30 slides. Keep each slide easy to scan. Use a maximum of 5 concise bullets per slide, with detailed instructions in speaker notes. Add a visual on every workflow slide: an application screenshot, a clearly labeled crop, or a simple diagram based on the actual interface.

1. **Title**
   - PH626 Kaakbay CDC LMS User Manual
   - Subtitle: Participant, Teacher, and Administrator Guide
   - Include version/date and a note that screens may change as the system is updated.

2. **How to Use This Manual**
   - Find the section for your role.
   - Follow numbered actions in order.
   - Read confirmation and error messages before trying again.

3. **What the LMS Does**
   - Central place for assignments, attendance, announcements, letters, gifts, and account information.
   - Explain that available pages depend on the signed-in role.

4. **Roles and Permissions at a Glance**
   - Participant/student: personal learning and submission tasks.
   - Teacher: participant support, assignments, announcements, and attendance.
   - Administrator: user, section, assignment, letter, gift, and announcement management.
   - Explain that users should only see tools permitted for their account.

5. **Before You Begin**
   - Supported browser and stable internet connection, if confirmed by the project environment.
   - Participant ID and password.
   - Keep credentials private.
   - Have files ready before uploading.

6. **Sign In**
   - Open the LMS login page.
   - Enter the Participant ID.
   - Enter the password.
   - Use the eye icon only when needed to check the password.
   - Select the login button.

7. **Sign-In Errors and Temporary Lockout**
   - Explain required-field messages.
   - Explain incorrect-credential errors without exposing sensitive details.
   - Explain that repeated failed attempts can trigger a timed lockout and that the countdown must finish before trying again.
   - Tell users to contact the LMS administrator if they cannot sign in after checking their details.

8. **The Main Screen**
   - Header, role-based sidebar, page banner, notification area, and notification button.
   - Explain the active-page indicator and notification badges.
   - Mention that notifications refresh when the page changes and when the window regains focus, if visible to the user.

9. **Navigation on Desktop and Mobile**
   - Select a sidebar item to open a page.
   - On smaller screens, open the drawer with the navigation toggle.
   - Select the backdrop or toggle to close it.
   - Explain the collapsed icon rail on larger screens.
   - Remind users to use the tooltip or label if an icon is unfamiliar.

10. **Account and Personal Settings**
    - Open **My Account**.
    - Review displayed personal information.
    - Explain which fields can be edited, based only on the live form.
    - Save changes and verify the success message.
    - Explain profile-photo selection if available.

11. **Theme and Session Controls**
    - Explain the light/dark theme toggle.
    - Explain logout and the confirmation dialog.
    - Recommend logging out on shared or public devices.

12. **Participant Dashboard and Notifications**
    - Explain the participant navigation.
    - Explain notification badges and the notification panel/button.
    - Explain what an unread, due, submitted, or returned item means only if the interface defines it.

13. **Participant: View and Submit an Assignment**
    - Open **My Assignment**.
    - Find an assignment and open its details.
    - Read instructions, due date, and any attached/downloadable materials.
    - Choose the file or work requested.
    - Upload it, review the selected filename, and select **Submit**.
    - Show how to recognize a successful submission.

14. **Participant: Review or Undo a Submission**
    - Explain how to check whether work is submitted.
    - Explain unsubmit/undo only if the control is available and describe its consequences clearly.
    - Warn users to resubmit after making changes when required.
    - Explain what to do when an upload fails.

15. **Participant: Write and Submit a Letter**
    - Open **My Letter Writing**.
    - Review the assigned letter or sponsor context.
    - Enter the letter using the available editor or fields.
    - Save a draft when available.
    - Submit the completed letter and check its status.
    - Explain revision requests and resubmission when shown.

16. **Participant: Gifts and Rewards**
    - Open **My Gift**.
    - Search or browse available gifts.
    - Read recipient, availability, and status information.
    - Explain how a gift is selected or claimed only if confirmed by the interface.

17. **Participant: Attendance**
    - Open **My Attendance**.
    - Move between months if available.
    - Read attendance marks and dates.
    - Explain how to report a suspected error to the teacher or administrator.

18. **Participant: Announcements**
    - Open **My Announcements**.
    - Search announcements when needed.
    - Open and read the full message.
    - Explain how to distinguish current information from older posts, if shown.

19. **Teacher Workspace Overview**
    - List the teacher pages: **My Account**, **Manage Participants**, **Manage Assignment**, **Post Announcement**, and **Check Attendance**.
    - Explain that teacher actions apply to their permitted participants or sections.

20. **Teacher: Manage Participants**
    - Open **Manage Participants**.
    - Create a participant account using the required fields.
    - Review the generated or entered Participant ID and assigned section.
    - Edit participant details when permitted.
    - Delete or deactivate only after checking the confirmation and impact.

21. **Teacher: Create and Manage Assignments**
    - Open **Manage Assignment**.
    - Create an assignment with title, instructions, section, due date, and attachments when available.
    - Save/post the assignment and verify success.
    - Review submissions and statuses.
    - Download or inspect submitted work when available.
    - Edit or delete only after confirming the effect on participants.

22. **Teacher: Post an Announcement**
    - Open **Post Announcement**.
    - Enter the title and message.
    - Choose the intended audience/section if the form provides that option.
    - Publish and verify that the announcement appears.
    - Delete or revise only when appropriate.

23. **Teacher: Check Attendance**
    - Open **Check Attendance**.
    - Select the relevant participant, date, month, or section.
    - Review existing records.
    - Enter or adjust attendance using the available controls.
    - Submit/save and verify the confirmation.

24. **Administrator Workspace Overview**
    - List the administrator pages: **My Account**, **Manage Users**, **Manage Sections**, **Manage Assignment**, **Manage Letters**, **Manage Gifts**, and **Post Announcement**.
    - Explain that administrators have broader controls and should verify changes carefully.

25. **Administrator: Manage Users and Sections**
    - Explain how to open participant, teacher, and administrator management areas.
    - Cover create, view, edit, and delete actions only where available.
    - Explain section creation, renaming, and deletion.
    - Add a warning to check dependencies before deleting a user or section.
    - Note that administrator creation may be restricted to an authorized primary administrator.

26. **Administrator: Manage Assignments, Letters, and Gifts**
    - Explain how administrators access assignment management.
    - Explain letter review, statuses, typed letters, uploaded letters, revision requests, and final handling only as confirmed by the interface.
    - Explain gift tracking and recipient selection.
    - Emphasize reviewing the target participant before saving.

27. **Administrator: Announcements**
    - Follow the same publish, review, and delete/revise workflow as the teacher section.
    - Emphasize checking the audience before publishing.

28. **Statuses, Messages, and Confirmations**
    - Create a small reference table for visible statuses such as draft, submitted, revise, pending, or completed.
    - Explain success messages, validation messages, upload errors, permission errors, and confirmation dialogs.
    - Tell users not to repeat an action when a request is still processing.

29. **Privacy, Security, and Good Practice**
    - Never share Participant IDs or passwords.
    - Avoid saving credentials on shared devices.
    - Check names, sections, recipients, files, and audiences before saving or publishing.
    - Upload only appropriate, required files.
    - Log out after use and report suspicious activity.

30. **Troubleshooting and Support**
    - Cannot sign in.
    - Account temporarily locked.
    - Page or button is missing.
    - Assignment or upload does not appear.
    - Letter, gift, attendance, or announcement data looks wrong.
    - Include a support escalation checklist: user name/Participant ID, role, page, action attempted, exact message, date/time, and screenshot without exposing the password.

31. **Quick Reference by Role**
    - Provide a one-page matrix of each role and its main pages/tasks.
    - Use icons and short action phrases for fast lookup.

32. **Closing Checklist**
    - Confirm important work was saved or submitted.
    - Confirm the success/status message.
    - Check notifications for follow-up.
    - Log out when finished.
    - Provide the confirmed support contact or leave a clearly marked placeholder.

## Visual and Design Direction

- Use the LMS visual identity: the PH626 Kaakbay CDC name and logo where available, with restrained orange, green, slate, and white accents.
- Use high-contrast text and large enough labels for projection and mobile viewing.
- Keep layouts clean and instructional, not promotional.
- Use numbered callouts directly on screenshots for click-by-click procedures.
- Include a consistent legend for **Select**, **Enter**, **Upload**, **Save**, **Submit**, **Back**, and **Logout**.
- Do not use fake screenshots or fabricated UI. If a screenshot is unavailable, use a simple labeled flow diagram and mark it as illustrative.
- Do not expose real passwords, private personal data, tokens, database values, or sensitive user records in screenshots.
- Add alt text or a short description for every important visual.

## Speaker Notes

For each workflow slide, add speaker notes containing:

1. The purpose of the task.
2. The exact numbered steps.
3. What success looks like.
4. Common mistakes and how to recover.
5. Any permission or role limitation.
6. A reminder to verify the live screen if the interface has changed.

## Final Quality Check

Before delivering the PowerPoint, verify that:

- Every role has a complete workflow section.
- Every page listed in the application navigation is covered.
- Login, lockout, navigation, notifications, theme toggle, profile photo, and logout are explained.
- Upload, save, submit, revise, delete, and confirmation behavior is explained where applicable.
- No unsupported feature or permission is presented as fact.
- Screenshots match the current application.
- Text is readable in presentation mode.
- The deck includes a quick-reference section and troubleshooting section.
- Export the final deck as both editable PowerPoint and PDF when possible.
